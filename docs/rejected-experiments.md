# Rejected experiments

Experiments that were implemented or bounded by measurement and then not shipped, kept so nobody repeats them. All numbers come from the same host as the README (RTX 3090 24 GB, 2x MI50 32 GB gfx906, ROCm 7.2.4). Models: Qwen3.8-27B (IQ3_S-based custom GGUF mix, 3.44 bpw, with an MTP head) and Qwen3.6-35B-A3B (IQ4_XS), unless a row says otherwise. Standard gates: at least +5% on the target metric, no class regressing by more than 2%, and fidelity (KLD, perplexity, greedy agreement) no worse than the noise floor of the same engine against itself. "Retried later" means the idea was reopened with a different implementation or a better measurement and rejected again.

| Experiment | Target | Idea | Measured result | Why rejected | Retried later |
|---|---|---|---|---|---|
| Chunked (Householder/WY) gated-delta-net prefill kernel | MI50 | Replace the scalar GDN recurrence with a chunked formulation to speed up prefill | Prefill 44-48% slower: 8k 22.8 s to 43.4 s, 32k 102.3 s to 183.0 s (about 360 to 188 tok/s). Fidelity was fine (36/36 backend op tests, greedy 17/20) | Gate failed on speed; Vega 20 has no matrix units, so the chunked form only adds work | no |
| Per-request runtime overhead patches (balanced ubatch, automatic prompt-cache disable, async and batched small input copies) | 3090 | Remove 100-130 ms of per-request overhead seen from outside the server | Best case -23 ms TTFT at 8k (-0.33%); 512-token prompt +1.8 ms; decode 77.4 to 76.9 tok/s. Greedy 20/20 identical | Below the -50 ms / 5% bar. The server HTTP loop itself costs 1.4-4.9 ms; the rest is the gateway in front of it and speculation misses | no |
| Prompt-cache in host RAM (`--cache-ram`) | 3090, MI50 | Keep recent prompts in RAM to skip re-prefill | Large TTFT gain only against a zero-cache baseline. Decode regressed in free generation: 3090 -3.1%, 27B on MI50 -3.0%, 35B on MI50 -2.2% (worst point -6.2%) | Decode regression above the 2% limit on every target; a later synthetic-workload run passed a non-regression gate for the 3090 but does not offset the free-generation results | yes (6-pair rerun passed only a narrow synthetic non-regression gate) |
| Q4_K decode matvec geometry sweep (13 variants of warps and rows per block) | 3090 | Retune the vocabulary-projection kernel (Q4_K, 682 MiB) | 816-821 us per launch for every variant; best candidate -0.37% [-0.63, -0.12] (worse in 5 of 6 pairs) | The kernel already reads at 875 GB/s, 98% of the measured read ceiling; no headroom | no |
| Shared-unpack `vec_dot` for IQ3_S / IQ3_XXS across 3 columns | 3090 | Decode each weight block once for three columns during speculative verify | Kernel bit-identical (56 processes); wall +0.49% [+0.20, +0.79] over 12 pairs; two windows disagreed | The compiler already shared the unpack (same instruction counts in the compiled code); the bottleneck is elsewhere | no |
| Native IQ3 MMQ path (prefill) | 3090 | Cheaper IQ3 weight/tile loads in the quantized matmul | Removing all IQ3 load cost would give +2.07% throughput; the kernel is issue-bound (3.6% of HBM peak) | Ceiling 2.4x below the 5% gate, so no kernel was written | no |
| IQ3_S repack and LDS tile changes for MMQ | MI50 | Pre-unpack IQ3_S weights; cut LDS traffic | Ceiling with the whole unpack removed: +2.52% prefill at 8k [2.32, 2.72]; removing LDS reads and stores made prefill 1.1-1.3% slower | Ceiling is half of the gate; LDS is not the limit | no |
| Decode-kernel geometry controls (flash-attention and fused-glue block sizes) | MI50 | Retune runtime-selectable geometry | Best alternatives -2.4% and -6.4% decode; the production default was on top | No setting beat the default; larger deviations lose up to 28% | no |
| AllReduce copy path rework after BF16 | MI50 | Faster staged copy between the two cards | Physical ceiling about +1% prefill: the x8 link of one card cannot do simultaneous device-to-host and host-to-device at full rate | Below the gate; probe only, nothing implemented | no |
| AllReduce overlapped with compute (micro-chunks) | MI50 | Hide the AllReduce behind the next chunk's compute | GEMM and copy overlap almost free (+0.8%), but splitting a 512 ubatch into 2x256 raises compute 13%; measured ceiling about -2.6%. An earlier overlap on top of the BF16 wire measured +0.3% prefill, -0.6% decode | Splitting costs more than it hides. The variant with a theoretical ceiling (two 512 halves in a 1024 ubatch) needs an asynchronous meta-backend, not built | no |
| INT8 AllReduce wire (per-32 FP16 scale) | MI50 | Halve the BF16 wire again | Prefill +4.17% [3.77, 4.57] (+4.4% in the first run), decode -0.35% (noise). KLD 0.00159 vs 0.00113 for the geometry-change floor (+41%); natural-text greedy agreement 77.3% vs 85.6% floor | Gain below 5% and fidelity worse than the noise floor on natural text | no |
| Adaptive MTP draft length (1 to 4 by recent acceptance) | 3090 | Raise n_max for code, lower it for dialogue | Aggregate decode -16.0% (39.2 to 32.9 tok/s); every class regressed: code -12.5%, dialogue -19.5%, Portuguese text -13.7% | Gate failed on all classes | yes (static n=3/4 first, then adaptive, see next rows) |
| Fixed MTP n_max = 3 or 4 by traffic class | 3090 | More draft tokens where acceptance is high | Code 8k: n=3 +5.6%, n=4 +25.7% (CI crosses zero); dialogue 8k: n=3 -7.2%, n=4 -21.5%; 129k n=4 -25.7% | Per-class regression above 2%; the corpus was cyclic and inflated acceptance | yes (rerun on natural text: n=3 +0.56% [-2.3, +3.4], third-draft acceptance 0.39-0.48 vs 0.51 needed) |
| MTP n_max = 1 | 3090 | Cheaper drafts when acceptance is low | Decode -6.2% to -8.0% on the 27B (95% CI below zero in three cells) at 65-70% acceptance. | Loses on the 27B | no |
| MTP n_max = 3 | MI50 | Third draft token with a sibling slot idle | Direct decode +3.1% [2.6, 3.7]; with a concurrent slot -2.8%; acceptance 74.6% to 66.9% | Below the 5% gate and costs concurrency | no |
| CUDA graph for the MTP draft step | 3090 | Cut launch overhead in the draft loop | First attempt -23% decode (a bug had silently switched speculation off, 30 tok/s is the no-speculation rate). Fixed version (per-shape graph results): aggregate decode +0.05% [-11.6, +11.7], wall -1.5% | The GPU is already 84% busy in the decode window and launches already overlap it; the "49% launch overhead" was host waiting on the GPU | yes (fixed launch variant, rejected again) |
| Host-gap reductions in MTP decode (recurrent-state checkpoint, backend sampling, graph reuse) | 3090 | Remove idle gaps between GPU steps | Measured ceilings: 0.4% + 1.2% + 1.6%, about 3.2% total | Cannot reach 5%; nothing was built beyond an opt-in profiler | no |
| Sampling pre-filter (top-k / argmax directly on logits instead of sorting 248k candidates) | MI50 | Save about 2.3 ms of CPU per speculative round | Bit-exact in unit tests and clear-margin prompts. Decode on the MI50: first run (n=5) +2.2-2.6%; rerun n=144 per arm +0.76% (+0.34 tok/s), CI [-0.35, +1.04] includes zero | The first result was noise; no measurable gain | yes (n=5 then n=144) |
| Fast logits path for the draft sampler | 3090 | Skip full-vocabulary work in the draft sampler | One slot: +2.5-2.9%; two slots mixed load +0.30% [-0.76, +1.36]; two-slot step -1.8% | Helps only a single slot; not a general gain | yes (the sampling fast path is included in the fork as an opt-in; it is what closes the single-slot decode gap to the deployed 3090 build, see the README) |
| Lean matvec variants (E1: decode shared across 3 columns for IQ3_S; E2/E2b/E2c: Q4_K gcn2v2 + DPP and 128-bit loads) | MI50 | Reduce redundant loads and instructions in the decode matvec during speculative verify (n=3) | E1 IQ3_S: n=3 +2.4-3.1% on 6 of 7 shapes but -2.6 to -3.0% on the dominant shape (m=5120, k=17408); modeled end-to-end gain 0.3-0.5% of decode. E2 Q4_K: n=3 +1.0 to +6% per shape (typical +2.6-3.2%), no regression, but only one shape passed the gate. E2b: n=3 +6.0-7.9% over E2 but n=1 -13 to -32%. E2c hybrid: n=3 +6.0-8.9%, n=1 neutral except one shape at -2.17% (CI includes zero). Serving A/B (35B, MTP): decode +1.19% (2k), +1.55% (8k), +0.19% (32k), PPL identical (5.8958), ranges overlap | Kernel gains of 6-9% on Q4_K at n=3 shrink to about +1% end to end because Q4_K is a small share of 35B decode; E1 regressed on the largest shape; the formal gate failed in every step | no |
| Native-precision (BF16/FP32-accumulate) prefill unlock | 3090 | Use the full-rate FP32-accumulate tensor path (BF16) for prefill GEMMs | Prefill 8k -5.08% time (7.94 to 7.54 s), 32k -3.50% (34.81 to 33.59 s); only two points per arm, drift between processes ~2.3%, so not a robust CI. Greedy agreement 11/20 on prompts that exercise the path (20/20 with the port off); +3.2 GiB VRAM (ubatch 4096); KLD/PPL not measured | The 8k gain sits at the edge of the 5% gate, with +3.2 GiB VRAM and numerical divergence; most prefill time is in INT8 MMQ and scalar GDN, which the unlock does not touch | no |
| Tensor-core gated delta net, first gate | 3090 | Tensor-core GDN prefill | PP +9.97% (27B) and +9.6-10.7% (35B) but greedy 14/20 (27B) and 9/20 (35B) against an exact-match gate | Excluded by the exact-match greedy gate; later accepted after the gate was redefined against the build's own run-to-run floor (see README fidelity table) | yes (accepted on re-evaluation, not rejected) |

Notes: percentages are of the stated metric, intervals are 95% CIs where shown, and N is small in several rows (the original reports state it). The 35B MoE is not bit-deterministic under concurrent slots against itself, so exact greedy identity is not used as a gate there.
